## 2. Module B: what the factory can actually produce

### 2.1 The real pipeline (what runs when a user clicks through)

Evidence: `apps/control-api/src/server.ts`, `core/workos/*`, `core/agents/first-delivery-bindings.ts`.

1. **Intake**: `POST /v1/intakes`, project/mission/task creation in the hash-chained Work OS journal (`core/workos/store.ts`, 910 lines; README documents journal format). CODED, INTEGRATED, TESTED(unit). (V)
2. **Pre-dev / analysis**: `POST /v1/missions/:id/analysis/step` and `/predev/produce`. `ClaudePreDevBuilder` asks Claude (read-only tools Read/Glob/Grep, profile "reviewer"-style) for one JSON artefact per kind: **5 kinds only: BusinessAnalysis, Requirements, Plan, Architecture, UxSpec** (`core/workos/predev/types.ts:19`). Validators check shape and traceability (goal ids -> requirement ids -> work packages -> components), not content quality. `approve/reject` endpoints record Founder decisions. (V)
3. **Plan -> tasks**: `POST /v1/missions/:id/plan` (max 50 tasks, `analysis.ts:MAX_PLAN_TASKS`), task status transitions with dependency gating, crew composition from the 599-role catalogue (rule-based recommendation only, `core/workos/crew/team-composer.ts`). (V)
4. **Run** (`MissionRunner`, `core/workos/runner.ts`, 1,161 lines): steps `WORKSPACE -> IMPLEMENT -> VERIFY -> SECURITY -> REVIEW -> REGRESSION -> REPORT` (`runner.ts:76`). IMPLEMENT = Claude CLI as implementer with **Read/Edit/Write/Glob/Grep only** (`BUILDER_ALLOWED_TOOLS`, `core/agents/role-execution.ts:33`; Bash/PowerShell/WebFetch/WebSearch/Agent/Task/Skill denied, `claude-profiles.ts:19`). The agent therefore cannot run its own code; every feedback loop goes through the runner. (V)
5. **VERIFY**: regex secret scan of the diff and commit messages (5 patterns, `secret-scan.ts:5-11`), static test-surface analysis (`test-surface.ts`, 264 lines: weakened/deleted/skipped tests are flagged), then the **test command runs only if `ExecutionGate` has a verified sandbox**; otherwise `tests: NOT_EXECUTED`, reason `SANDBOX_UNAVAILABLE`, run continues to SECURITY (`runner.ts:929-937`). (V)
6. **SECURITY**: gitleaks and trivy are used only if installed on PATH; semgrep is only discovered, never run (`security-tools.ts:283`: SAST is always `NOT_AVAILABLE`, reason `TOOL_INSTALLED_NOT_INTEGRATED` or `TOOL_NOT_INSTALLED`). Missing tools are recorded as partial gaps, not blockers (`security-tools.ts:280-281`). (V)
7. **REVIEW**: a second Claude profile (read-only) returns `{"verdict":"CLEAN"|"BLOCKED","findings":[]}`; implementer and reviewer identities must differ (`assertIndependentExecutors`, `executors.ts:48`); invalid output is never CLEAN. Remediation cycles loop back to IMPLEMENT. (V)
8. **Delivery**: `prepareRunDelivery` (`project-studio.ts:485-555`) writes a ZIP containing `source/` (all files of the run commit, no `.git`), `README.md` and `VERIFICATION_STATUS.json`, hashed (SHA-256) and bound to run+mission+commit. README states "Nothing in this package was executed by UASCO" and "not a merge, release or production deployment." The Founder can record `SOURCE_DELIVERY_ACCEPTED`. (V)
9. **Product run** (`POST /v1/work-runs/:id/product`, `core/workos/devrun.ts` 641 lines): starts the delivered app only inside a verified sandbox; unavailable otherwise (`DEVRUN_SANDBOX_UNAVAILABLE`). (V by code and locale strings.)

Default project templates: **3** (`web-node` dependency-free http server + index page + node:assert test, `node-lib`, `empty`) (`core/workos/project-templates.ts`, 131 lines). (V)

## Known issue found by the review (not in this diff, fixed separately)
The pre-dev start and approve flows each write two or three separate journal entries (`core/workos/predev/driver.ts` `start`, `approveAndAdvance`). If the phase-advance write fails after the earlier write succeeded (disk full 507, append I/O error, or a crash between the two fsyncs), the sequence stays in its old phase and the API cannot move it: a repeated start answers `200 replayed` at `AUTHORIZED`, and a repeated approve answers `409 PREDEV_ARTIFACT_TRANSITION_ILLEGAL` because `APPROVED` is terminal. No data is lost or forged, and no gate is bypassed. The flow is stuck instead. The fix (finish the pending advance on retry) belongs to the pre-dev driver and route owners and goes in its own non-protected PR, so this batch only registers the routes.

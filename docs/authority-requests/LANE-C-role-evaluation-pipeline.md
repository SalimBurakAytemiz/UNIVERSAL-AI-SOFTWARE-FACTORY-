# LANE-C authority request: governed role evaluation pipeline (C-EVAL-PIPELINE)

Coordinator-approved package. It builds the pipeline whose absence the protected validator names (`FA_WFR03_EVALUATIONS_EXECUTED: no governed evaluation pipeline exists`). **It does not raise TESTED.** Today the registry says tested 0 / certified 0 and that stays true until the two protected steps below are taken on purpose.

## What exists after this package
- `core/competency/evaluation-pipeline.ts`: `runRoleEvaluation(deps, roleId, "EV-01")`. It checks the role binding, runs ONE defined procedure on the real executor adapters, computes the verdict only from deterministic oracle checks (model text never decides), and stages the evidence in the verifier's exact format.
- `scripts/run-role-evaluation.mjs` (+ `core/competency/evaluation-cli.ts`): the operator CLI.
- Procedures (all `EV-01 ROLE_SPECIFIC_GOLDEN_MISSION`; the registry spec text is NOT in this repository, so each procedure states what it covers and does not cover and says so in the evidence):
  - `golden-file-v1` (developer UASCO-0085): follow a precise single-file mission. Oracle: the engine-owned commit exists, only `greeting.txt` was added, its bytes are exactly `hello\n`, regular file, within the role's file limit.
  - `golden-review-v1` (security-reviewer UASCO-0252): CLEAN with no findings for a trivially correct diff, BLOCKED with at least one finding for a planted command injection, review clone left untouched.
  - `golden-predev-v1` (pre-dev primaries 0022, 0023, 0019, 0043, 0031; uses the #205 `ClaudePreDevBuilder`): the existing artifact validators accept the output for the TaskHub reference brief and approved upstream.
  - Every other role/evaluation (tester, delivery, 590 unbound roles, EV-02..EV-06) is refused with `NO_PROCEDURE` / `ROLE_NOT_EXECUTABLE`: there is nothing honest to run.
- Pre-dev empty or oversized replies (the process exited 0) are the role's own FAILED result; every other builder failure is infrastructure. The pipeline's own timeout (default 60 min, tightened by the role limit and `deps.timeoutMs`) is enforced for the pre-dev path too and recorded as `TIMEOUT`. A review clone that was not clean before the review, or a clone/workspace the pipeline cannot inspect, is infrastructure.
- Outcomes: `EVALUATED` (PASSED/FAILED, evidence staged), `NOT_EXECUTED` (infrastructure: timeout, abort, non-zero exit, profile/provenance/workspace refusal, no builder, invalid review; **nothing is staged**, the role is neither lifted nor penalised) or `REFUSED`. Builder refusals that are the role's own behaviour (no change, touched `.git` or agent config, forbidden path) are `FAILED`.

## Safety properties (each pinned by a test and a mutation check)
- Staging root is `<Work OS data dir>/evaluations/staging` (fixed; the CLI has no output-path flag). It must resolve **outside** the repository and not be an ancestor of it; symlinks (root, any component below it, the role dir, a pre-existing target file) are refused; names are fixed (`EV-0n.json`, `EV-0n.artifact.json`), role/evaluation ids are validated, nothing is ever overwritten (atomic `link`; an existing or partial pair is refused BEFORE the executor starts). The pipeline never writes to `audit/evidence/**`, `registries/**` or any repo path, and never edits a registry status.
- `executorKind` is the pair's own kind, never a caller input. A FAKE pair always produces `executorKind:"FAKE", fake:true`, which `createEvidenceVerifier` rejects (`FAKE_EVIDENCE`); the pipeline reports `verifier.countsIfPromoted`.
- Artifact and evidence files are secret-redacted on the string values before serialisation (so a key at the start of a line is caught too; the hash binds the redacted bytes). The temporary repositories never inherit ANY `GIT_*` variable (repository selectors such as `GIT_DIR`, and config injection such as `GIT_CONFIG_PARAMETERS` / `GIT_CONFIG_COUNT`), and every git command of the pipeline runs with `core.fsmonitor=false` so a user-level git config cannot make git run a program in them. The staging root must be a real path: a symlink or junction anywhere in its ancestry is refused (pass a data dir without aliases), and a root that cannot be created or linked into is refused before the executor starts (writability is probed and the probe leaves no trace).
- CLI: dry run by default (prints plan, the control root it used and `executeBlockers`; no process, no file, not even the staging dir). The **control root** is resolved exactly like the server does (`apps/control-api/src/server.ts`): `--control-root`, else `UASCO_CONTROL_ROOT`, else the repository root (an empty value counts as absent). Executor state (enable setting, `PROVIDER_PROVENANCE.json`, launcher sha256) and the Claude profiles are all read under that one root. `--execute` is refused unless: not in `CI` / `GITHUB_ACTIONS`; `config/automation.json` `allowPaidApi` is exactly `false`; LOCAL_CLAUDE is enabled by the Founder (persisted setting in `<data dir>/settings/executors.json` or the explicit env selection) and READY (provenance PASS, launcher sha256 unchanged) in that control root; **the Claude profile the role will really use is usable**: `implementer` for the developer/tester route, `reviewer` for the reviewer and the pre-dev builder, each reported by the dry run as `CLAUDE_PROFILE_<ROLE>_REFUSED:<reason>` (for example `PROFILE_PATH_INSIDE_GIT_WORKTREE` when the control root is inside a git checkout, which is the default when neither flag nor variable is given and the repository root is a checkout) or `CLAUDE_PROFILE_<ROLE>_LOGIN_REQUIRED` (the Founder has not logged that profile in). Then it builds the pair only from `LocalClaudeExecutors` (no personal-profile fallback). It is also refused while `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE` and the like, or git-config injection (`GIT_CONFIG_PARAMETERS`, `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_<n>`, `GIT_CONFIG_VALUE_<n>`), are set in the environment (the adapters' own git calls would inherit them). CI never runs it.

## Operator run (Founder; real model; never in CI)
```
node scripts/run-role-evaluation.mjs --role UASCO-0085 --data-dir <Work OS data dir> --control-root <control root>            # dry run: read executeBlockers
node scripts/run-role-evaluation.mjs --role UASCO-0085 --data-dir <Work OS data dir> --control-root <control root> --execute  # real run
```
`--control-root` may be omitted when `UASCO_CONTROL_ROOT` is set to the same value the Work OS server runs with; with neither, the repository root is used and the profile check will report `PROFILE_PATH_INSIDE_GIT_WORKTREE`. The dry run must show `"executeBlockers": []` first.
Evidence lands in `<data dir>/evaluations/staging/audit/evidence/role-evaluations/<roleId>/EV-01.json` (+ `.artifact.json`). To re-run, the staged pair must be moved away deliberately.

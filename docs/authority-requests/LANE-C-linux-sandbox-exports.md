# LANE-C note: C-LINUX-SANDBOX-EXPORTS tests live in the registered `tests/v7-int-r3-sbx-gate.test.ts` (no registration needed)

Package C-LINUX-SANDBOX-EXPORTS (coordinator request for Lane B's `claude/lane-b-sbx-win-1`, `docs/authority-requests/LANE-B-wsl-sandbox.md`). `core/agents/linux-unshare-sandbox.ts` now exports `LINUX_SANDBOX_NS_FLAGS`, `LINUX_SANDBOX_HELPER_PATH` and `LINUX_SANDBOX_SETUP`, the unchanged values the provider runs with. The only non-alias change: `NS_FLAGS` is `Object.freeze`d (typed `readonly string[]`), so a consumer cannot mutate the provider's isolation flags through the shared array; the provider only spreads it.

The 2 tests (under 1 s) are the `C-LINUX-SANDBOX-EXPORTS` describe at the end of the already-registered `tests/v7-int-r3-sbx-gate.test.ts` (step `tests-5`, which already tests this provider); the separate file `tests/v7-lane-c-linux-sandbox-exports.test.ts` was removed, so `tests/pkg-vs-validation-sharding.test.ts` stays green without a `config/validation.json` change. They pin (1) the literal values, the frozen array, `PATH=<exported helper path>` inside the exported script; (2) that the provider's own private argv builder returns `[...exported flags, shell, "-c", exported setup, ...]` for the same inputs (nothing is executed).

## C-SBX-LO-1 (stacked on this package): loopback inside the sandbox
The 6 tests are the `C-SBX-LO-1` describe at the end of the same registered `tests/v7-int-r3-sbx-gate.test.ts` (step `tests-5`): no registration. They take about 17 s (the Linux-only cases check the host first and skip visibly elsewhere); the whole file takes about 25 s on a root Linux host with `perl` and a writable `/usr/sbin` (the stub-`ip` case runs a real `selfTest` four times); about 12 s elsewhere (that case is skipped, with the reason in the test source). Keep it in a Linux-capable shard; the real-provider cases skip themselves when the host cannot create the namespaces.
`SETUP` now runs `ip link set lo up` (resolved with the fixed helper PATH, before the capabilities are dropped; no fallback to any other tool). `selfTest` proves: loopback works inside, `/proc/net/route` has no route, nothing inside reaches the internet or the host's 127.0.0.1 listener. `provider.capabilities` is `{loopback, loopbackReason}` (`LOOPBACK_TOOL_MISSING`, `LOOPBACK_PROBE_NODE_UNAVAILABLE`, `NOT_PROBED`). One reason code beyond the agreed list: `SELFTEST_OUTBOUND_NOT_VERIFIED` (the probe started but died before its verdict: fail closed). `acceptUnenforcedProcessLimit` gets no new caller.
Mutants: `docs/lanes/LANE-C-sbx-lo-mutants.json` and `.mjs` (`node docs/lanes/LANE-C-sbx-lo-mutants.mjs`; commit first, it refuses a dirty tree).

## Security review fixes (LC-LO-01..03, first security review of 0fe60a6 / 99f5395: NO_BLOCKERS)
- LC-LO-01 (MED): `selfTest` also requires the sandbox's net namespace (`readlink /proc/self/ns/net`, printed by the shell isolation probe) to DIFFER from the host's (`SELFTEST_NETNS_SHARED`; a missing line or unreadable host link is `SELFTEST_NETNS_NOT_VERIFIED`). A loopback probe that printed nothing counts as "node unavailable" ONLY for exit code 127 without a timeout; any other silent result (crash, timeout, nonzero exit, silent success) fails closed with `SELFTEST_LOOPBACK_PROBE_FAILED`, so AVAILABLE can no longer be reported without the host-loopback/outbound negative probe having run. The pure helpers `netnsProblemOf(isoStdout, hostNetns)` and `hostNetns()` are exported for Lane B's WSL selfTest (LC-LO-04).
- LC-LO-02 (LOW): `provider.capabilities` returns a frozen copy on every read; an in-process holder can no longer flip `loopback` to unlock the nsenter bridge.
- LC-LO-03 (LOW): scripted-`exec` tests exercise selfTest's wiring (host listener connection count, route check, netns check, the port handed to the probe, capabilities published only after EVERY later step, frozen getter); a missing pre-flight tool skips them, it does not pass them. Mutants N1-N10 added (28 in total, all killed).
- Not done: the optional node-free fallback probe (3); LC-LO-04/05 belong to Lane B's WSL provider.

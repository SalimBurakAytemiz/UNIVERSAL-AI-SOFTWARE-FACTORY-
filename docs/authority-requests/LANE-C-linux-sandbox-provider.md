# LANE-C authority request: register the free Linux sandbox provider (v2)

## STATUS: v1 (PR #168) was NOT safe; register only v2 (this document's code)
An independent adversarial review of v1 reproduced HIGH escapes: the whole host filesystem stayed readable (home dirs, `~/.ssh`, other projects), host pathname unix sockets (docker/dbus/ssh-agent) stayed connectable, `/dev` `/dev/shm` `/sys` and any mount under a path starting with `/dev|/sys|/proc` or containing a space stayed writable, a root supervisor's kuid 0 kept DAC over `/proc/sys`, the timeout kill was bypassable (the project was pid 1 and could clear `PR_SET_PDEATHSIG`), and `selfTest` passed while all of this was exploitable. v1 was never wired (no runtime effect). **Do not apply any registration hook until v2 is merged.**

## What v2 does (no protected file touched; util-linux `unshare`, `setpriv`, `pivot_root`, `mount`, `awk` only)
- A new tmpfs root replaces the host root (`pivot_root`, old root detached): only `/usr`, `/bin`,`/lib*`,`/sbin` (symlinks recreated), ONLY the `bin` and `lib` directories of the node install prefix (when node lives outside `/usr`) and `/etc/alternatives`,`/etc/ld.so.*` are bind-mounted read-only; a synthetic `/etc/passwd|group|nsswitch.conf`; private `/dev` with six safe nodes and a private `/dev/shm`; private `/tmp`; the working directory is `/work` (the only host-visible writable path); `/proc` is mounted read-only with `/proc/sys`, `sysrq-trigger`, `irq`, `bus`, `fs` read-only and `kcore|keys|timer_list|sched_debug|kmsg` masked; **no `/sys`, no `/home`, `/root`, `/run`, `/var`, `/mnt`**. Host unix sockets, secrets and other projects are not reachable.
- Every run audits `/proc/self/mountinfo` after the pivot and exits 126 if any mount other than `/work`, `/tmp`, `/dev/shm` is not read-only (fail closed, no deny-list).
- The project is never pid 1: a tiny capability-less supervisor `sh` is pid 1 and runs the project as a child, so the project cannot clear the namespace init's `PDEATHSIG`; when `unshare` is killed the whole pid namespace is torn down with SIGKILL. All capabilities dropped (`Cap* = 0`, `no_new_privs`); nested user namespaces disabled (`max_user_namespaces=0`).
- Helper tools run with a fixed system `PATH` before the privileged phase, and `setpriv`, `prlimit` and the supervisor shell are resolved to ABSOLUTE paths with that fixed `PATH` before the capability drop; the caller's `PATH` applies only to the project after the drop (a planted `setpriv`/`prlimit`/`sh` shim never runs, including via `/work`, relative or empty `PATH` entries). A self-review found that the first v2 cut still resolved the final `exec setpriv` through the caller's `PATH` (a planted `/work/setpriv` ran with `CapEff=000001ffffffffff`); fixed and covered by a regression test. `spawn()`/`run()` require an explicit `env` (no host `process.env` inheritance).
- ulimits: CPU seconds (timeout + 5 s), address space (16 GiB default), per-file size, process/thread count (`maxProcesses`, see F3). On timeout or abort the host SIGKILLs the whole process GROUP (the sandbox is started in its own session), not only the direct child.

## Coordinator review of ef978d5 (F1-F5) and what changed
- **F1 (toolchain root could expose a home directory): fixed.** The default root set is no longer `dirname(dirname(execPath))`. `nodeToolchainRoots()` requires the node prefix layout (`bin/node` plus `lib/node_modules` or `include/node`), binds only `<prefix>/bin` and `<prefix>/lib`, and binds nothing (node is then simply absent in the sandbox) if the prefix is a home directory or contains one, is a broad directory (`/opt`, `/home`, `/var`, ...), or has a sensitive entry (`.ssh`, `.claude`, `.aws`, `.gnupg`, `.kube`, `.docker`, `.config`, `.npmrc`, `.netrc`, `.git-credentials`, `.env`). Explicit `readOnlyRoots` go through the same `readOnlyRootProblem()` check. The selfTest probe `extra_roots_isolated` proves that inside the sandbox the parent directories of every bound root list only the path components leading to it (no siblings, no `.ssh`).
- **F2 (controlling terminal / TIOCSTI): fixed.** `run()` starts `unshare` in a new session (`detached`/setsid) and `spawn()` always sets `detached: true`; the `/dev/tty` device node is no longer bound. The selfTest probe `no_ctty` requires `tty_nr == 0` and no `/dev/tty`; the test starts the provider under a real pty (host `tty_nr != 0`) to make it non-vacuous.
- **F3 (no process-count limit): fixed as far as the kernel allows.** `ulimit -u` does not exist in dash, so `prlimit --nproc` is used (`maxProcesses`, default 4096). The selfTest runs a fork probe with a small cap through the same code path and requires forks beyond it to FAIL (`SELFTEST_PROCESS_LIMIT_NOT_ENFORCED` otherwise). Measured: the kernel exempts kuid 0 (init user) from `RLIMIT_NPROC`, so with a **root supervisor the limit cannot be enforced** and the default provider therefore stays UNVERIFIED (fail closed). `acceptUnenforcedProcessLimit: true` is an explicit operator opt-in (selfTest then returns `{ok: true, detail: "PROCESS_LIMIT_NOT_ENFORCED_ACCEPTED"}`); whether the cloud (root) deployment may use it is a decision for the wiring hook / the Founder. A non-root supervisor is verified with the limit proven.
- **F4 (session keyring inherited): documented residual**, unchanged.
- **F5 (pid-1 supervisor ptrace under `ptrace_scope=0`): mitigated.** The host no longer relies on the namespace init's `PDEATHSIG`: on timeout/abort it SIGKILLs the whole process group, including the init, and SIGKILL cannot be blocked by a tracer. The selfTest's hostile child now also tries `PTRACE_ATTACH` on pid 1 and must still die at the timeout. (`ptrace_scope` is not present on this container's kernel, so the attach itself was not demonstrated to succeed; the kill path does not depend on it.)
- `selfTest()` now uses host canaries (file, listening unix socket, `/dev/shm` file) that the sandbox must not see, plus: supervisor pid 1, hidden host dirs, read-only root, writable scratch/tmp/private-shm (and host check that the shm file is not visible), `/proc/sys` writes blocked, in-sandbox mount audit, all five `Cap*` zero + `NoNewPrivs`, no network interface, nested userns blocked, private pid namespace, an adversarial child (ignores TERM, `setsid`, clears `PR_SET_PDEATHSIG`, writes after timeout) that must die, and stdin forwarding. Any failure => UNVERIFIED => `run()`/`spawn()` refuse (never host execution).

## Residual risks (documented, not fixed)
- Shares the host kernel; no seccomp filter (kernel attack surface remains), no cgroup memory/pids limits (ulimit + timeout only), no disk quota on `/work` (host directory; `/tmp` and `/dev/shm` are size-limited tmpfs). A large write to `/work` is bounded only by the timeout. Process/thread count: `RLIMIT_NPROC` (`maxProcesses`, default 4096, set with `prlimit` when available, skipped if the host hard limit is lower) is enforced by the kernel only when the supervisor is NOT kuid 0 (verified: as uid 65534 forks beyond the cap fail; as root the kernel exempts init-user kuid 0, 300/300 forks succeed, and `pid_max` is not writable inside the namespace). On a root supervisor a fork bomb is therefore bounded only by the timeout, so the default provider does NOT verify there (F3); `acceptUnenforcedProcessLimit: true` accepts this knowingly. Run the control API as a non-root user.
- When the supervisor is root (kuid 0), the project process keeps kuid 0 file ownership semantics on what it can see (read-only system dirs, `/work`); it cannot see `/home`, `/root`, `/sys`, `/run` or write `/proc/sys`. Prefer an unprivileged supervisor user.
- The invoker's kernel session keyring is inherited (no `keyutils` dependency to replace it); make sure the factory process holds no secrets in its session keyring.
- Needs unprivileged user namespaces. Ubuntu 24.04 GitHub runners restrict them (AppArmor), so there the provider reports `SELFTEST_NAMESPACES_UNAVAILABLE` and refuses; the isolation tests then only assert the refusal and the positive proof comes from hosts that allow user namespaces (the Linux cloud container).
- `PRODUCT_VERIFIED` must still not be claimed from this alone; whether it counts as a verified sandbox (FD-REL-1) is the Founder's call.

## Windows design notes (provider stays NOT_IMPLEMENTED)
Reports `PLATFORM_NOT_LINUX_NOT_IMPLEMENTED`. A real Windows provider needs a Job Object (`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`, active-process, memory and CPU-time limits) plus a restricted token / AppContainer (low integrity), network denied by AppContainer without `internetClient` or a WFP filter, filesystem via explicit ACL on the workspace only, started by a small native helper. Node alone cannot create these without a native addon or helper binary (new dependency/binary), so this needs an authority decision and can be marked implemented only after a self-test passes on `windows-latest`.

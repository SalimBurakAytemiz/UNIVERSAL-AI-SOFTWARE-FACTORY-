# LANE-C authority request: C-FLOW-ANALYSIS-2, real analysis content through the Claude CLI

## Question asked: does a production BuilderPort backed by LocalClaudeExecutors with the pre-dev role profiles exist and is it wired?
Yes. `ClaudePreDevBuilder` (`core/workos/predev/claude-builder.ts`) is what `LocalClaudeExecutors.pair().preDevBuilder` returns (`core/workos/executors.ts`); `apps/control-api/src/routes/predev-decisions.ts` (`POST .../predev/produce`) calls it and maps `PreDevBuilderError` to 502 `PREDEV_BUILDER_FAILED {reason: <code>}`; `AnalysisFlow` (C-FLOW-ANALYSIS-1) takes it as its `BuilderPort`. It uses the reviewer-route authority only (provenance-verified launcher, separate read-only reviewer profile, read-only tool list, isolation flags, `allowPaidApi` env policy, an empty scratch directory outside the repo, process-group kill on timeout/stop). No new authority, no env flag, no API key.

## Gaps found and closed (all in Lane C paths)
1. **Output was free text.** The CLI was started with `--output-format text`: a login error, a max-turns stop or a refusal arrived as stdout and was indistinguishable from content. Now `reviewerArgv(launcher, "json")` (same tools and isolation flags, only the format differs) and the runtime option `outputFormat: "claude-json"` make the builder read the CLI's single result envelope (`type:"result"`, `subtype`, `is_error`, `result`). Output is the `result` text of a successful envelope only. Default (`"text"`) behaviour of the builder is byte-for-byte unchanged for other callers.
2. **Exact failure codes** (new, `PreDevBuilderFailure`), classified as follows (#237 review): `PREDEV_BUILDER_LOGIN_EXPIRED` ONLY from the documented auth envelope (`is_error:true`, `subtype:"success"`, `result` starts a line with the existing auth matcher, whatever the exit code) or from the STDERR of a process that exited non-zero; the text of any other envelope (`error_during_execution`, `error_max_turns`, ...) or of plain stdout is never an auth signal, because it can be model or tool output. `PREDEV_BUILDER_CLI_ERROR` for EVERY parsed error envelope (`is_error:true` or a non-`success` subtype), whatever the exit code (rate-limit and API errors included). `PREDEV_BUILDER_ENVELOPE_INVALID` when stdout is not a result envelope (not JSON, an array, `type` other than `result`, `is_error` missing or not a boolean, no `result` text). `PREDEV_BUILDER_EXIT_NONZERO` for a non-zero exit with no envelope and no auth text on stderr. Text mode (no `outputFormat`) classifies nothing: unchanged. Existing codes keep their meaning (`TIMEOUT`, `EMPTY_OUTPUT`, `SCRATCH_MODIFIED`, `PROVENANCE_REFUSED`, `PROFILE_REFUSED` ...). The 502 route already passes any code through as `reason`. **No Founder action text is attached to `PREDEV_BUILDER_LOGIN_EXPIRED` in this package** (an earlier version of this note claimed one in `analysis.ts`; that was wrong): `AnalysisFlow` answers `BUILDER_FAILED {kind, code}` and the Desktop/route layer owns the wording (Lane B request: show "sign in again with the reviewer profile" for this code).
3. **Fences.** If the ENTIRE reply is one ``` / ```json fence, only the wrapper is removed (the content is untouched and still goes through the validators). Prose before/after the JSON, two fences or text that is not JSON are NOT repaired: the driver answers `REJECTED PREDEV_DRIVER_INVALID_JSON`.
4. **Output skeletons.** `composeRolePrompt` now ends with a per-kind JSON skeleton (`OUTPUT_SKELETONS`, exact validator key sets; traceability slots are placeholders, not ids). A test fills every skeleton and runs the REAL validator chain (G1 -> FR1 -> S1/WP1 -> C1), so the skeletons cannot drift from `validators.ts`.
5. **Placeholder guard (shared, #237 review).** The skeletons for BusinessAnalysis and UxSpec are shape-valid, so a lazy reply that echoes one would pass the validators. The guard lives in `core/workos/predev/placeholder.ts` and runs INSIDE `validateArtifactContent`, before the shape check, so every caller gets it: `PreDevDriver.produceCurrentPhase` (which still answers its exact `REJECTED PREDEV_DRIVER_PLACEHOLDER_VALUE` first), the store write gate (`recordPreDevArtifact` -> `apply.ts`: `PREDEV_ARTIFACT_INVALID:PLACEHOLDER_VALUE`, nothing appended), `CrewCoordinator.reproduceSuperseding` (`CREW_REWORK_INVALID:PLACEHOLDER_VALUE`, previously unguarded) and the competency evaluation. It scans every string and every key at any depth, iteratively (no recursion: a reply nested 100 000 deep is the typed rejection `CONTENT_TOO_DEEP`, depth cap 32, never a `RangeError`/500), after NFKC normalisation and removal of Unicode format characters (`\p{Cf}`), case-insensitively, allowing whitespace between the chevrons and `FILL`, and requiring a word boundary after `FILL`: `<<FILL>>`, `<<fill`, `<< FILL`, `＜＜ＦＩＬＬ`, `<<F<ZWSP>ILL` are all rejected, `<<fillable>>` or "the FILL level" are honest text. Not done (optional in the review): rejecting the exact skeleton hint texts without the marker; that is a content-quality question and the Founder approves every draft. **Replay note:** `validateArtifactContent` also runs when a journal is replayed, so a journal that already holds an artefact whose content contains the marker would fail replay as `PREDEV_ARTIFACT_INVALID:PLACEHOLDER_VALUE`; no such artefact can exist (the marker is introduced by this package and every write path now refuses it), and the validators are already re-applied at replay by design.
6. **No retry.** One produce = one process = one paid call. A rejection or failure never re-spawns on its own; the next call is the Founder's next `step`.

## Gap found by Lane B: ready readiness but no production builder (closed)
`claudeAnalysisReadiness` could say `ready` while local Claude was not enabled (no executors pair, or a FAKE pair that has no `preDevBuilder`); `step()` then answered `BUILDER_FAILED / PREDEV_DRIVER_BUILDER_NOT_CONFIGURED` and the route 502. Now `step()` answers `BLOCKED {blocker: "EXECUTOR_NOT_ENABLED", blockers: [..., "EXECUTOR_NOT_ENABLED"], founderAction: "... open Settings, then Executors, and enable LOCAL_CLAUDE ..."}` BEFORE any paid call and before anything is opened or recorded. The check uses the builder the route already passes (`getExecutors().pair?.preDevBuilder?.() ?? NO_ANALYSIS_BUILDER`): `NO_ANALYSIS_BUILDER` means "no production builder". **The Lane B route (`claude/lane-b-analysis-routes` @0e22e16) and the `claudeAnalysisReadiness({controlRoot, profile, cli})` call stay unchanged.** `claudeAnalysisReadiness` additionally accepts an optional `executorEnabled?: boolean` (`false` adds the same blocker, after the CLI/launcher/sign-in blockers because the executor can only be enabled once the CLI exists) for a future readiness-only endpoint. The old test that pinned the 502 behaviour was updated to the new contract (stricter, not weaker); a builder that throws `NOT_CONFIGURED` itself still maps to `BUILDER_FAILED`.
Tests (host `tests/v7-core-predev-crew-coordination.test.ts`): ready + no pair -> BLOCKED; ready + FAKE pair -> BLOCKED; LOCAL_CLAUDE pair -> unchanged and produces; readiness option order. Mutants E1-E4 in `docs/lanes/LANE-C-flow-analysis-2-mutants.json`.

## The fake CLI (what "fake CLI process" means here)
`runReviewer` (existing programmatic test injection of `LocalClaudeExecutors`) is pointed at a wrapper that calls the REAL `runProcess` with `[node, fake-claude.mjs, ...argv]`. The script reads the prompt from stdin, logs argv / cwd / pid / `CLAUDE_CONFIG_DIR` / any API-key env names, then replies per a scenario file (envelope, plain text, stderr, exit code, sleep, stray file in its cwd, echo of the skeleton). So spawn, stdin, stdout/stderr capture, exit codes, timeout kill (the pid is checked dead), scratch cleanup and env are the production ones; only the model is missing.

## Remaining gap to a real Founder run (exact)
1. **Never run against the real CLI here.** No login, no paid call was made (not authorised). The envelope shape (`type:"result"`, `is_error`, `subtype`, `result`) is the documented `claude -p --output-format json` shape and the installed CLI lists `--output-format` and `--json-schema`, but a real envelope has not been recorded. First Founder run: capture one redacted envelope as a fixture. If the real shape differs, the result is `PREDEV_BUILDER_ENVELOPE_INVALID` (fail closed), never a fake pass.
2. **Model compliance is unproven.** Real replies may add prose or fences more often than the prompt allows; whole-reply fences are unwrapped, everything else is rejected with the exact code and costs one paid call per attempt. `--json-schema` (CLI-enforced schema) was NOT used because its failure behaviour is unverified without a paid call; the validators remain the gate.
3. **Content quality is not judged** by any test (structure + traceability only); the Founder approves each draft (independent actor + evidence, existing store gates).
4. **Routes + screens not wired:** `POST /v1/missions/:id/analysis/step|plan` (protected `server.ts` wave, see the C-FLOW-ANALYSIS-1 request) and the Desktop screens that show `BLOCKED` / `DRAFT_READY` / `REJECTED` / `BUILDER_FAILED`. Until then the existing `predev/produce` route reaches the same builder but without `claudeAnalysisReadiness` gating or plan creation.
5. **Windows / Electron not executed.** `.cmd` shims stay unsupported (protected provenance capture). The process-group kill and detach paths are the existing ones.
6. **Prompt budget:** the largest prompt (Architecture with all upstream) stays far below the 256 KiB builder limit for a one-idea project; a very large brief would be rejected `PREDEV_BUILDER_PROMPT_INVALID`.

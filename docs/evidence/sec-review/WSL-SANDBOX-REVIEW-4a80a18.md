## [HIGH] WSL-INTEROP-STALE-SELFTEST: Interop verified once per process; re-enabling WSLInterop after startup gives host code execution with no re-check
- Where: `core/sandbox/wsl-unshare-sandbox.ts:220` (UNVERIFIED_WSL)
- Path and fix: selfTest() memoizes probe() with `this.probing ??=` (line 220-221) so the interop gate in probe() (OUTER_SCRIPT at line 128, INTEROP_ENABLED at line 244) runs exactly once per Control-API process. run() (line 183-185) then only re-checks the boolean this.verified. The WSLInterop binfmt_misc handler is registered kernel-globally and (with the F flag) survives mount namespaces and pivot_root, so it is NOT neutralised by the sandbox. Attacker/host condition: the Founder (or anything in that distro) re-enables interop (e.g. `echo 1 > /proc/sys/fs/binfmt_misc/WSLInterop/status` or edits /etc/wsl.conf and the daemon restarts interop) after the process started. From then on every run() executes an untrusted PE dropped in /work on the Windows host via /init = host code execution, while the provider still reports AVAILABLE. Depends on WSL fact: binfmt_misc registration persists independent of the sandbox mount namespace, and interop can be toggled at runtime. Minimal fix: re-run the cheap interop negative check (one `wsl -d <distro> --exec` reading binfmt_misc + a PE-exec probe) at the start of every run()/exec(), and fail closed (SANDBOX_NOT_VERIFIED) if interop is now active, instead of trusting a startup-only selfTest.

- Where: `core/sandbox/wsl-unshare-sandbox.ts:114` (UNVERIFIED_WSL)

## [HIGH] LC-1: WSL selfTest returns AVAILABLE without any lifecycle negative probe (timeout and process-tree teardown, process-limit enforcement, stdin, kill tool); AVAILABLE where the Linux provider refuses
- Where: `core/sandbox/wsl-unshare-sandbox.ts:250` (CODE_READING)
- Path and fix: In probe(), after the isolation probe, run the same lifecycle probes the Linux provider requires (linux-unshare-sandbox.ts:239-259), through the same stageSandbox/run.sh path inside WSL. (a) Process-limit probe: stage with a small nproc and require forks beyond it to fail; otherwise return PROBE_PROCESS_LIMIT_NOT_ENFORCED. This catches a root default user (`wsl --import` distros and `[user] default=root` both run --exec as kuid 0, which the kernel exempts from RLIMIT_NPROC) and a missing prlimit (SETUP lines 36-38 skip it silently). (b) Timeout probe: a short-timeout command that ignores TERM and starts a background child that writes a marker file after the deadline. Require result.timedOut and no marker file, and require that a follow-up `pgrep -f <scratch>` finds nothing. (c) An abort probe through the shouldAbort path, with the same no-survivor check. (d) A stdin round trip. (e) Add pkill, pgrep and prlimit to the TOOLS list in OUTER_SCRIPT (line 130). Any failure must leave the provider unverified.

## [MEDIUM] WSL-INTEROP-FILE-PROBE-VACUOUS: INTEROP_FILE in-sandbox probe is always 'absent' (binfmt_misc is never mounted in the sandbox's fresh /proc), so it cannot detect active interop
- Where: `core/sandbox/wsl-unshare-sandbox.ts:104` (CODE_READING)
- Path and fix: PROBE_SCRIPT line 104 tests `[ -e /proc/sys/fs/binfmt_misc/WSLInterop ]` and PROBE_EXPECT line 116 requires INTEROP_FILE=absent. The reused LINUX_SANDBOX_SETUP mounts a FRESH proc (`mount -t proc ... "$R/proc"`) and never mounts the separate binfmt_misc filesystem, and the host binfmt_misc mount is detached by pivot_root. So /proc/sys/fs/binfmt_misc/WSLInterop is unconditionally absent inside the sandbox regardless of whether the handler is registered and active kernel-wide. This negative probe therefore always passes and is non-load-bearing; it gives false assurance that interop is inactive. The only real interop gates are OUTER_SCRIPT (line 128, run outside the sandbox) and the PE_EXEC behavioral probe. Minimal fix: drop the INTEROP_FILE probe or replace it with a check that actually reflects global state (behavioral PE exec, or mounting binfmt_misc read-only to read status), and document that interop detection relies on the OUTER check, so a future refactor cannot mistake INTEROP_FILE for a working gate.

## [MEDIUM] WSL-PE-EXEC-HEURISTIC-WEAK: PE_EXEC probe uses a 6-byte malformed PE and accepts exit 126/127 as 'interop off'; a false pass permits a real PE to run on the host
- Where: `core/sandbox/wsl-unshare-sandbox.ts:105` (UNVERIFIED_WSL)
- Path and fix: PROBE_SCRIPT line 105-106 writes `MZ\220\000\003\000` (a 6-byte stub, not a loadable PE) to /work/probe.exe and execs it; PROBE_EXPECT line 115 treats exit 126 or 127 as 'cannot execute' = interop inactive. Host condition: if WSLInterop is registered but binfmt_misc is unmounted in the distro (OUTER then reads INTEROP=absent, line 128/244) and WSL's /init returns 126/127 when it fails to launch a MALFORMED PE, the selfTest passes while interop is actually live; a real valid PE in /work would then be executed on the Windows host (host code execution). Also, if the registered magic/mask does not match the 6-byte stub, the kernel falls through to ENOEXEC and the shell reports 127 (MZ bytes = command not found), masking an active handler. Depends on WSL facts (the WSLInterop magic/mask and /init's exit code for a malformed image) that could not be run here. Minimal fix: probe with a minimal VALID PE (so it reaches /init), and treat only the specific shell-ENOEXEC-fallthrough outcome as 'interop off' - any other exit = interop active = fail closed; combine with a robust registration check in OUTER rather than relying on absence of the binfmt file.

## [MEDIUM] LC-3: Abort (GLOBAL_STOP / lease loss) only kills wsl.exe; the Linux-side tree can keep running up to the full timeout because cleanup's pkill is unverified, ignored, and does not kill the namespace's process group
- Where: `core/sandbox/wsl-unshare-sandbox.ts:169` (UNVERIFIED_WSL)
- Path and fix: UNVERIFIED. This depends on the WSL fact that TerminateProcess/taskkill on wsl.exe does not signal the Linux process it started over --exec. Because of that, the abort at line 90 does not stop the sandbox, and the only Linux-side stop is cleanup's `/usr/bin/pkill -KILL -f -- S` at line 169. pkill is missing from the TOOLS check at line 130, its exit code is ignored, and it races with a late-starting process. ## [MEDIUM] LC-4: /work writes have no size limit and can persist: an untrusted project can make cleanup's rm -rf fail, failures are ignored, and stale scratch directories are never swept
- Where: `core/sandbox/wsl-unshare-sandbox.ts:170` (REPRODUCED)
- Path and fix: `/work` is a bind mount of WSL /tmp/uasco-sbx-*/work (linux-unshare-sandbox.ts:56), which is on the distro's ext4.vhdx with no quota. A project can write large amounts within the 10-minute timeout. If it sets a directory to mode 000, the outer non-root user's `rm -rf` cannot descend into it. Reproduced as uid 65534: 'rm: cannot remove .../work/locked: Permission denied' and the scratch stays; `chmod -R u+rwX` followed by rm removes it. Cleanup ignores the failure (lines 168-171), and a host crash skips the finally block entirely. Fixes: (1) run `chmod -R u+rwX -- S` before `rm -rf`, then check `test ! -e S` and report a failure; (2) sweep /tmp/uasco-sbx-* older than the maximum timeout during selfTest; (3) preferably back /work with a size-capped tmpfs mounted inside the sandbox's mount namespace, with the archive extracted there, so writes have a hard limit and disappear with the namespace.

## [LOW] LC-7: The Windows kill helper can taskkill /T /F a PID that has exited (and may have been reused) and runs a blocking spawnSync every 100 ms while an abort is pending
- Where: `core/sandbox/wsl-unshare-sandbox.ts:87` (UNVERIFIED_WSL)

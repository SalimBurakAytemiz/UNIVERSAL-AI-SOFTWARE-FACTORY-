# LANE-C map (agents / Work OS / tools)

- Definition vs running agent: `core/agents/role-execution.ts` — `RoleExecutionProfile` (data on a role definition) vs `RunningAgent` (needs EXECUTABLE resolution + runId; tool gate; trace envelope).
- Bindings: `core/agents/first-delivery-bindings.ts` — pre-dev primaries business analyst UASCO-0022, requirements engineer 0023, UX designer 0031, then planner 0019, architect 0043, developer 0085, tester 0313, security reviewer 0252, delivery 0232. All other roles: `NOT_EXECUTABLE:ROLE_HAS_NO_BINDING`.
- Certification: never granted; `EVALUATED_PASS` only if all catalog evaluationSpecs PASSED with evidence (today 0/3594).
- Tools: only `config/builder-execution-policy.json` allowedTools; reviewer-route read-only; delivery uses no model tools (ProjectStudio).
- Wired: `crewDevExecutors` (core/workos/crew/dev-review.ts) is fail-closed via `assertRoleExecutes` (developer / security-reviewer). Team summary reports per-role executability (read-only). Runner IMPLEMENT step blocks a run whose roleId has no executable developer binding (roleId null = unchanged). Next: widen guild by guild.
- Routing/recovery: `core/agents/agent-routing.ts` — read-only provider route readiness (no login => NOT_READY, never personal profile) and agent checkpoint/restore (fail-closed on corruption, missing/changed/incomplete binding).
- Runner IMPLEMENT gate accepts implementer-route roles (developer 0085, tester 0313) via `assertImplementerRole`.
- Run evidence: role-assigned runs write `AGENT_TRACE` for IMPLEMENT (bound implementer) and REVIEW (bound security-reviewer, verdict in note). REVIEW BLOCKS before any review call if the reviewer role binding is missing/incomplete (`RunnerOptions.reviewerRoleId` overrides the default UASCO-0252). Per-call tool trace stays NOT_OBSERVABLE_FROM_ADAPTER.
- Sandbox (v2, after adversarial review): minimal pivot_root root, project never pid 1, per-run mountinfo audit, canary-based selfTest; v1 (#168) was unsafe and never wired - see docs/authority-requests/LANE-C-linux-sandbox-provider.md.
- Tests: tests/v7-b3a-runner.test.ts (LANE-C role gate + AGENT_TRACE); `tests/v7-core-predev-team-composer.test.ts` ("LANE-C role execution resolver").
- Runner claim cap (C5a): `RunnerOptions.maxConcurrentRuns` (default 1, valid 1..16, else `RUNNER_MAX_CONCURRENT_RUNS_INVALID`). A tick takes a lease only while fewer than the cap runs are owned (new claims and stale-lease takeovers); the rest stay QUEUED and are reported in `TickReport.deferred`. Fixes: with several queued runs the old tick leased all of them up front and drove them serially, so a queued run's lease expired unrenewed while an earlier run executed and it was fenced and later "recovered" (spending recovery budget). Owned runs are driven together (`Promise.all`); cap 1 is the old serial behaviour. Not done: workspace cleanup after terminal states (ProjectStudio reads run commits from `runs/<id>/work/.git/objects`, so deleting the workspace needs a commit-retention design first).
- Task limits (C3a): the runner applies a bound role's `TaskLimits` to its run via `effectiveLimits` (only ever tightens the run defaults): `maxCycles` -> at most `maxCycles-1` remediations (`*_TASK_LIMIT_MAX_CYCLES_EXHAUSTED`), `timeoutMs` -> implementer timeout, `maxFilesWritten` -> files changed vs the run base after IMPLEMENT (`TASK_LIMIT_FILES_EXCEEDED:<n>><max>`, BLOCKED before VERIFY; unreadable count -> `TASK_LIMIT_FILES_UNVERIFIABLE`). Role-less runs are unchanged. Developer/tester `timeoutMs` = 60 min (the runner's existing default). REVIEW-stage limits follow once #176 lands.
- Profiles (C2): `scripts/build-role-execution-profiles.mjs` (+ `--check`, byte-identical rebuild) derives `registries/role-execution-profiles.json` for all 599 roles from in-repo sources only via `core/agents/role-profile-derivation.ts`. Every field is PROPOSED_DERIVED with provenance; empty fields carry a gap id; write route only with SEMANTIC_VERIFIED technical legacy evidence, otherwise read-only; never production/network/secret/payment/deployment grants; reviewer != self. It is a proposal, NOT a binding: nothing becomes executable/tested/certified from it.
- SANDBOX NOTE: the v1 provider (#168) was NOT VERIFIED (independent review reproduced HIGH escapes) and is replaced by the hardened v2 in `core/agents/linux-unshare-sandbox.ts` (PR #184). v2 passed the coordinator's static re-review (F1-F5) but has had no independent runtime review; it is not wired and must only be registered by the coordinator for a non-root supervisor with `selfTest` ok and no `acceptUnenforcedProcessLimit`.
- Lifecycle (C1): `core/agents/role-lifecycle.ts` computes REGISTERED/IMPLEMENTED/TESTED/CERTIFIED/RUNNING as five independent counters from evidence only (verifier mirrors scripts/validate-role-registry.mjs + rejects FAKE evidence); `STAGE_CONSUMERS` in first-delivery-bindings.ts is the single source of "which stage consumes which binding". Route module `apps/control-api/src/routes/role-status.ts` (registration: docs/authority-requests/LANE-C-role-status-route.md).

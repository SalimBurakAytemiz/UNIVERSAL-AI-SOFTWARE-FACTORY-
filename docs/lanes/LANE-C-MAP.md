# LANE-C map (agents / Work OS / tools)

- Definition vs running agent: `core/agents/role-execution.ts` — `RoleExecutionProfile` (data on a role definition) vs `RunningAgent` (needs EXECUTABLE resolution + runId; tool gate; trace envelope).
- Bindings: `core/agents/first-delivery-bindings.ts` — pre-dev primaries business analyst UASCO-0022, requirements engineer 0023, UX designer 0031, then planner 0019, architect 0043, developer 0085, tester 0313, security reviewer 0252, delivery 0232. All other roles: `NOT_EXECUTABLE:ROLE_HAS_NO_BINDING`.
- Certification: never granted; `EVALUATED_PASS` only if all catalog evaluationSpecs PASSED with evidence (today 0/3594).
- Tools: only `config/builder-execution-policy.json` allowedTools; reviewer-route read-only; delivery uses no model tools (ProjectStudio).
- Wired: `crewDevExecutors` (core/workos/crew/dev-review.ts) is fail-closed via `assertRoleExecutes` (developer / security-reviewer). Team summary reports per-role executability (read-only). Runner IMPLEMENT step blocks a run whose roleId has no executable developer binding (roleId null = unchanged). Next: widen guild by guild.
- Routing/recovery: `core/agents/agent-routing.ts` — read-only provider route readiness (no login => NOT_READY, never personal profile) and agent checkpoint/restore (fail-closed on corruption, missing/changed/incomplete binding).
- Runner IMPLEMENT gate accepts implementer-route roles (developer 0085, tester 0313) via `assertImplementerRole`.
- Run evidence: role-assigned runs write `AGENT_TRACE` for IMPLEMENT (bound implementer) and REVIEW (bound security-reviewer, verdict in note). REVIEW BLOCKS before any review call if the reviewer role binding is missing/incomplete (`RunnerOptions.reviewerRoleId` overrides the default UASCO-0252). Per-call tool trace stays NOT_OBSERVABLE_FROM_ADAPTER.
- Sandbox (v2, after adversarial review): minimal pivot_root root, project never pid 1, per-run mountinfo audit, canary-based selfTest; v1 (#168) was unsafe and never wired - see docs/authority-requests/LANE-C-linux-sandbox-provider.md.
- Tests: tests/v7-b3a-runner.test.ts (LANE-C role gate + AGENT_TRACE); `tests/v7-core-predev-team-composer.test.ts` ("LANE-C role execution resolver").
- Runner claim cap (C5a): `RunnerOptions.maxConcurrentRuns` (default 1, valid 1..16, else `RUNNER_MAX_CONCURRENT_RUNS_INVALID`). A tick takes a lease only while fewer than the cap runs are owned (new claims and stale-lease takeovers); the rest stay QUEUED and are reported in `TickReport.deferred`. Fixes: with several queued runs the old tick leased all of them up front and drove them serially, so a queued run's lease expired unrenewed while an earlier run executed and it was fenced and later "recovered" (spending recovery budget). Owned runs are driven together (`Promise.all`); cap 1 is the old serial behaviour. Not done: workspace cleanup after terminal states (ProjectStudio reads run commits from `runs/<id>/work/.git/objects`, so deleting the workspace needs a commit-retention design first).
- Task limits (C3a): the runner applies a bound role's `TaskLimits` to its run via `effectiveLimits` (only ever tightens the run defaults): `maxCycles` -> at most `maxCycles-1` remediations (`*_TASK_LIMIT_MAX_CYCLES_EXHAUSTED`), `timeoutMs` -> implementer timeout, `maxFilesWritten` -> files changed vs the run base after IMPLEMENT (`TASK_LIMIT_FILES_EXCEEDED:<n>><max>`, BLOCKED before VERIFY; unreadable count -> `TASK_LIMIT_FILES_UNVERIFIABLE`). Role-less runs are unchanged. Developer/tester `timeoutMs` = 60 min (the runner's existing default). REVIEW stage (security-reviewer `lim(1, 0, 60 min)`): `timeoutMs` -> reviewer timeout via `effectiveLimits` (min of run default and role limit); `maxFilesWritten` 0 is the existing untouched-clone gate (`REVIEWER_MUTATED_CLONE`) plus `profileDefect`; `maxCycles` 1 = one review pass per REVIEW step (the remediation loop is bounded by the implementer role's `maxCycles`). Changing a binding limit requires `node scripts/build-role-execution-profiles.mjs`.
- Profiles (C2): `scripts/build-role-execution-profiles.mjs` (+ `--check`, byte-identical rebuild) derives `registries/role-execution-profiles.json` for all 599 roles from in-repo sources only via `core/agents/role-profile-derivation.ts`. Every field is PROPOSED_DERIVED with provenance; empty fields carry a gap id; write route only with SEMANTIC_VERIFIED technical legacy evidence, otherwise read-only; never production/network/secret/payment/deployment grants; reviewer != self. It is a proposal, NOT a binding: nothing becomes executable/tested/certified from it.
- SANDBOX NOTE: the v1 provider (#168) was NOT VERIFIED (independent review reproduced HIGH escapes) and is replaced by the hardened v2 in `core/agents/linux-unshare-sandbox.ts` (PR #184). v2 passed the coordinator's static re-review (F1-F5) but has had no independent runtime review; it is not wired and must only be registered by the coordinator for a non-root supervisor with `selfTest` ok and no `acceptUnenforcedProcessLimit`.
- Lifecycle (C1): `core/agents/role-lifecycle.ts` computes REGISTERED/IMPLEMENTED/TESTED/CERTIFIED/RUNNING as five independent counters from evidence only (verifier mirrors scripts/validate-role-registry.mjs + rejects FAKE evidence); `STAGE_CONSUMERS` in first-delivery-bindings.ts is the single source of "which stage consumes which binding". Route module `apps/control-api/src/routes/role-status.ts` (registration: docs/authority-requests/LANE-C-role-status-route.md).
- Pre-dev production (C-PREDEV-PRODUCE): `core/workos/predev/claude-builder.ts` `ClaudePreDevBuilder` (BuilderPort) runs the bound pre-dev primary (`PRE_DEV_ROLE_MAP[kind][0]`) on the SAME authority as the reviewer route (provenance-verified launcher, reviewer profile, `reviewerArgv`, `allowPaidApi=false`) in an empty scratch dir outside the repo; role binding is asserted before any process; scratch change / timeout / non-zero exit / empty or oversize output are typed `PREDEV_BUILDER_*` failures; timeout kills the process group. `LocalClaudeExecutors.pair().preDevBuilder` (FAKE pair has none). `core/workos/predev/brief.ts` derives the brief only from recorded mission/project fields. Route `POST /v1/missions/:id/predev/produce` in `predev-decisions.ts` (gates, ONE produce at a time across all missions (`PREDEV_PRODUCE_IN_PROGRESS` same mission / `PREDEV_PRODUCE_BUSY` other), Global Stop re-checked after the process exits (423, nothing recorded), 201 DRAFT / 422 rejected output / 502 builder failure, audit `WORKOS_PREDEV_PRODUCED`; allowed for R3/R4 (no project code runs); never approves). `STAGE_CONSUMERS.PREDEV_PRODUCE` moves IMPLEMENTED 3 -> 8; requests: `docs/authority-requests/LANE-C-predev-produce.md` (Desktop allow-list path + one `server.ts` line). NOT_VERIFIED with a real model.
- Run workspace archive (C5b, default OFF): `core/workos/run-archive.ts` `RunWorkspaceArchiver.sweep()` archives a terminal managed run's RECORDED commit set (headSha + evidence commitSha's) under `refs/uasco/run-commits/<runId>/<sha>` (+ `refs/uasco/runs/<runId>` for the head) via the existing ProjectStudio import, re-verifies each without alternates, writes `runs/<id>/workspace-archive.json`, then removes derived clones and `runs/<id>/work` after the retention period. Never for open runs, non-managed projects, symlinked paths, secret-flagged runs (objects would leak into later clones), or when archive/verification fails; bounded work per pass with backoff. Server hook: docs/authority-requests/LANE-C-run-workspace-archive.md (env `UASCO_RUN_WORKSPACE_RETENTION_HOURS`).
- Role evaluation pipeline (C-EVAL-PIPELINE): `core/competency/evaluation-pipeline.ts` `runRoleEvaluation` runs ONE defined EV-01 golden-mission procedure per bound role (developer `golden-file-v1`, tester `golden-tests-v1` (static oracle, nothing executed), security-reviewer `golden-review-v1`, the five pre-dev primaries `golden-predev-v2` (v2: prompts carry output skeletons, a placeholder echo is FAILED)) on the real executor adapters, computes the verdict only from deterministic oracle checks and STAGES verifier-format evidence under `<Work OS data dir>/evaluations/staging` (outside the repo, no symlinks, never overwritten; never `audit/evidence`, `registries` or a registry status). FAKE pairs are always stamped FAKE and never count; infrastructure trouble is `NOT_EXECUTED` and stages nothing. `scripts/run-role-evaluation.mjs` (+ `evaluation-cli.ts`) is a dry run by default; `--execute` needs not-CI, `allowPaidApi=false`, Founder-enabled READY LOCAL_CLAUDE. Promotion and the narrowing of the validator's `evaluationSpecsExecuted:0` invariant (incl. FAKE rejection in its `evidenceProblem`) are protected steps: `docs/authority-requests/LANE-C-role-evaluation-pipeline.md`. TESTED stays 0 until then.
- Role readiness audit (C-RDY-1): `core/agents/readiness-audit.ts` `computeRoleReadiness` is the AUTHORITATIVE readiness measurement: 8 tri-state layers (DEFINED, PROFILED, KNOWLEDGE_READY, TOOL_READY, EXECUTABLE, EVALUATED, INTERNALLY_CERTIFIED, RUNNING; TRUE/FALSE/UNKNOWN with closed reason codes and real denominators) per canonical role, rolled up for 51 guilds and 10 clusters, plus `EXECUTABLE.stageWired` reported SEPARATELY (never merged, never defaulted: UNKNOWN without `reachableStages`). A JSON status is never evidence, PROPOSED_DERIVED data is never PROFILED, no empty list is TRUE, RUNNING is UNKNOWN (not 0) unless the journal is explicitly PRESENT with a runs array (`RunsObservation` in `core/agents/role-lifecycle.ts`; undefined or unknown values are ABSENT), a group with denominator 0 is never `measured` (coordinator-approved amendment to the dispatch after the #260 review: `measured = denominator > 0 && UNKNOWN === 0`), duplicate guild / binding / proposed-profile keys are an input error (`READINESS_INPUT_INVALID:<code>:<key>`; a duplicate ROLE id stays a DEFINED finding), a non-default `promotedTechnologyStatuses` is disclosed in `inputs` and labels the result NON_AUTHORITATIVE_PROMOTED_STATUS_OVERRIDE, and `PROMOTED_TECHNOLOGY_STATUSES` is the empty set until FD-1/FD-9 decide. EXECUTABLE/EVALUATED/INTERNALLY_CERTIFIED call `roleLifecycle()` (no rule copy); `computeRoleStatusSummary` is `@deprecated` (DEPRECATED_LEGACY_PROJECTION, byte-compatible) and `reconcileLegacyStatusSummary` compares it to the audit in total and per guild. `loadReadinessInputFromRepo` reads six registry groups read-only and throws `READINESS_INPUT_UNAVAILABLE:<path>` instead of substituting empty data; empty `roles` / `guilds` / `clusters` / `skills` arrays are rejected the same way (amendment above). It changes no model behaviour and no user-visible number; Lane B (B1) and Lane A (A1) consume it later. Test: `tests/v7-core-readiness-audit.test.ts`; mutants: `node docs/lanes/LANE-C-readiness-audit-mutants.mjs` (M1-M25 plus X1-X15 from the #260 review).

# Cloud next-task dispatcher (operating note)

Authority: Founder directive 2026-10-18 (Cloud-only dispatch infrastructure, non-protected files). This is NOT FA-LEASE2 wiring and does not touch protected orchestrator files.

```
node docs/planning/dispatch.mjs [--claim] [--owner <id>] [--backlog <path>] [--remote <name>]
                                [--base-branch v7/integration] [--stale-hours 6] [--open-prs a,b] [--no-lease]
```

Prints one JSON line `{outcome, taskId, branch, claimRef, reasons[], ...}`. Exit: 0 START/NO_ACTION, 2 BLOCKED, 3 RECOVERABLE_FAILURE.

## Selection (fail-closed)
First task in file order with: `status === "READY"`, `owner === "CLOUD"`, `authorizedBy` a non-blank string, `dependsOn` an array of strings all present and `DONE`, `protectedEdit` absent or `false`, `requiresNewAuthority` absent or `false` (strict booleans; `"true"`, `null`, `0` are malformed and rejected), a well-formed id (see below), no remote branch `claude/<id-lowercase>`, no ref conflict, no remote branch equal to `task.branch`, and not in `--open-prs`. Every rejected task gets machine-readable reasons (`NOT_READY:<s>`, `NO_AUTHORIZED_BY`, `UNMET_DEP:<id>`, `PROTECTED_EDIT`, `REQUIRES_NEW_AUTHORITY`, `ALREADY_CLAIMED`, `REF_CONFLICT`, `BRANCH_EXISTS:<b>`, `OPEN_PR:<b>`, `MALFORMED_*`). Missing/unparseable/non-array backlog or duplicate ids => BLOCKED. Unreachable remote => RECOVERABLE_FAILURE (never "no work").

Id validation (`MALFORMED_ID`, the task is skipped and the queue continues): the id must match `[A-Za-z0-9][A-Za-z0-9._-]{0,127}`, contain no `..`, not end with `.`, not end with `.lock` in any case (`/\.lock$/i`), and both the FINAL lowercased claim branch `claude/<id-lowercase>` (`git check-ref-format --branch`) and the lease ref `refs/uasco/claims/<id>` (`git check-ref-format`) must be accepted by git (spawned with an args array). A malformed id never reaches a push.

Ref conflicts (`REF_CONFLICT`, skipped): a remote head starting with `claude/<id-lowercase>/` (e.g. `claude/df-1/work`) or a remote head equal to a directory prefix of the claim ref (e.g. a branch named `claude`) would make the claim push impossible; the task is skipped and the queue continues.

## Claim
`--claim` pushes a one-commit claim (parent = remote `--base-branch` tip, same tree, subject `dispatch-claim: ...`) to `refs/heads/claude/<id-lowercase>` with `--force-with-lease=<ref>:` (create-only). If that ref already exists the push fails, the claim is lost and the next selectable task is tried (auto-advance). It also records the claim via the merged `automation/lib/task-lease.mjs` + `task-lease-git-store.mjs` remote ref store (`refs/uasco/claims/<id>`, TTL = `--stale-hours`, sessionId = `<owner>:<pid>:<random UUID>`), imported read-only, BEFORE the branch push. `--no-lease` disables the lease record.

Lease outcomes (`lease.status` in the JSON):
- `GRANTED`: lease recorded.
- `HELD` (a valid lease record owned by someone else exists): the task is skipped with reason `<id>:LEASE_HELD` and the next task is tried.
- `LEASE_STORE_UNAVAILABLE`: the lease write failed, no record is readable and the lease ref does not exist on the remote (e.g. the server rejects `refs/uasco/*`, or the lease modules throw). This is NEVER reported as `HELD`. The "lease ref absent" conclusion requires a SUCCESSFUL `git ls-remote` with empty output; if that `ls-remote` itself FAILS (non-zero status) the dispatcher is fail-closed: the task is skipped with reason `<id>:LEASE_CHECK_FAILED` and the queue continues. `LEASE_STORE_UNAVAILABLE` can also arise from lock contention (a failed lease write with no readable record); this has no integrity impact because the branch push remains the arbiter. Documented fail-safe: the dispatcher PROCEEDS with the branch-ref claim, because the branch ref is the arbiter, and reports `lease.status = "LEASE_STORE_UNAVAILABLE"` plus reason `<id>:LEASE_STORE_UNAVAILABLE`. No lease record exists for that claim, so downstream consumers must not assume one.
- `SKIPPED`: `--no-lease` or the lease modules could not be loaded.

Push failures: a lost race (ref now exists) => `CLAIM_RACE_LOST`, next task. Any other push failure for one task (hook rejection, etc.) => reason `<id>:PUSH_FAILED:<CODE>` (CODE from the closed vocabulary below; the stderr is classified, never echoed) is recorded, the lease (if granted) is released, and the queue CONTINUES with the next task. `RECOVERABLE_FAILURE` is returned only when the remote cannot be listed (`ls-remote` fails: `REMOTE_UNREACHABLE` at start, or `<id>:PUSH_FAILED_REMOTE_UNREACHABLE` after a failed push), when the base is unavailable, or on `CLAIM_COMMIT_FAILED` (the granted lease is released first). If every attempted push failed but the remote is reachable, the outcome is `NO_ACTION` with the `PUSH_FAILED` reasons.

Failure classification (closed vocabulary; NO remote text is ever echoed). Server, hook and lease-module error text is untrusted and may contain credentials, so it is never copied into any output field. `pushFailReason(stderr)` matches the (bounded, lower-cased) stderr against fixed patterns, first match wins, and returns exactly one code from this set: `NON_FAST_FORWARD`, `REF_CONFLICT_REMOTE`, `REF_LOCKED`, `PROTECTED_BRANCH`, `AUTH_FAILED`, `PERMISSION_DENIED`, `HOOK_DECLINED`, `NETWORK`, `REMOTE_REJECTED`, `UNKNOWN` (anything unrecognised). The JSON reason is exactly `<id>:PUSH_FAILED:<CODE>`. When the lease module throws, the same classifier yields `lease.error = "LEASE_ERROR:<CODE>"`. There is no redaction layer and no debug switch: because nothing from the remote is echoed, there is nothing to redact. To see the raw diagnostics an operator re-runs the failing push by hand (`git push <remote> <sha>:refs/heads/claude/<id> --force-with-lease=refs/heads/claude/<id>:`) in their own terminal.

The same ls-remote gating applies when the lease module itself throws: a failed `ls-remote` => `LEASE_CHECK_FAILED` (task skipped); successful empty => `LEASE_STORE_UNAVAILABLE` (branch claim proceeds); lease ref present => treated as held (`LEASE_HELD`, skipped). The thrown error is reported only as `LEASE_ERROR:<CODE>`.

## Output contract (stdout)
Exactly one JSON line. Every string in it is either (a) a fixed code written in this script, or (b) a value that passed a strict validator; nothing else can reach stdout:
- Backlog text is sanitised before it is echoed: task ids only if they pass the id validation (else `?`, including in `perTask[].taskId`, `UNMET_DEP:<id>` and `BACKLOG_DUPLICATE_ID:<id>`); `NOT_READY:<status>` only for a status in a fixed enum (the orchestrator package statuses plus `AUTHORITY_REQUIRED, DRAFT_NOT_READY, IN_REVIEW, BLOCKED, DONE, READY, IN_PROGRESS, PENDING_REVIEW, PENDING_CI, NOT_STARTED, COMPLETED`), else `malformed`; `OWNER_NOT_CLOUD:<owner>` only for `CLOUD|LOCAL|FOUNDER`, else `malformed`; `BRANCH_EXISTS:<b>` / `OPEN_PR:<b>` only for a ref-valid name of at most 120 chars, else the fixed code `BRANCH_INVALID`; unknown argv flags are shown as `ARG_UNKNOWN:?` unless they look like a plain flag. Every string in `reasons` (and `perTask[].reasons`) is cut at 160 chars. Note that `_` is a legal character in ids/refs, so a token-shaped but syntactically valid id (e.g. `abc_123`) is a valid id and is echoed; only text that fails validation is replaced.
- `ls-remote` output is parsed strictly: a line is used only if the sha is 40 or 64 lowercase hex and the head name passes the ref validation (`[A-Za-z0-9][A-Za-z0-9._/-]{0,200}`, no `..`, no trailing `.` or `.lock`); any other line is ignored, so `baseSha` and the arguments passed to git never contain arbitrary text. Consequence: a remote head with characters outside that set (e.g. `+`, `@`, spaces) is invisible to selection and to conflict detection; a push that collides with it is then reported as `PUSH_FAILED:<CODE>`.
- Lease info: `lease.status` is a fixed code. The lease module's status is accepted only if it is exactly `GRANTED` or `HELD`; any other value skips the task with reason `<id>:LEASE_ERROR:UNKNOWN`, and nothing is released that was not obtained. `lease.token` is echoed only if it matches `[A-Za-z0-9.:-]{1,256}` (real tokens are `<owner>:<pid>:<uuid>:<epoch>:<uuid>`; `_` is excluded on purpose so token-shaped secrets are never echoed), `lease.epoch` only if it is a safe integer; otherwise the field is omitted. `lease.error` is `LEASE_ERROR:<CODE>` and `leaseErrorCode` never throws.
- Remote, hook and lease-module text is never echoed (see classification below). Any unexpected exception inside `run()` yields exactly `{"outcome":"RECOVERABLE_FAILURE","reasons":["INTERNAL_ERROR"]}` with exit code 3.

Failure codes are ADVISORY LABELS. They come from pattern-matching text that the remote, a server hook or a lease module controls, and the order is first match wins; a hook can therefore make its rejection look like another code (for example `NETWORK` or `PERMISSION_DENIED`). Use them to help a human triage; never gate a decision on one. `timed out`, `ssl` and `tls` match only as whole words.

## Recovery
A claim is `RECLAIMABLE` (reported only, never deleted) when its ref has no commits beyond base other than `dispatch-claim` commits, the claim commit tree equals the base tree, the newest claim commit is older than `--stale-hours`, and its branch is not in `--open-prs`. A claim whose tree differs from base is `HAS_WORK_COMMITS`. A future-dated claim (negative age) is `UNKNOWN` (`CLAIM_AGE_NEGATIVE_FUTURE_DATED`), never `FRESH`. States also reported: `FRESH`, `OPEN_PR`, `UNKNOWN`. An operator must delete the ref (and `refs/uasco/claims/<id>`) by hand to release it.

## Exact limitations
- What IS atomic: the git server's create-if-absent on the single claim ref. Two concurrent dispatchers can never both create it; the loser sees a rejected push. Likewise the lease ref create.
- What is NOT: this is a branch-ref claim, not the merged atomic lease protocol as scheduler authority and not FA-LEASE2 wiring. Nothing in the orchestrator reads these claims, and the branch-ref claim and the lease ref are two separate pushes (not one transaction): a crash between the two pushes (lease first, then branch) can leave a lease without a claim branch; that lease stays held, and the task is skipped as `LEASE_HELD`, until the TTL (`--stale-hours`) expires (no auto-release). Such lease-only orphans (lease without branch) are NOT in the `RECLAIMABLE` report, which only covers existing claim branches. The reverse (branch without lease) happens when the lease store is unavailable. A lost-race or failed-push lease is released best-effort.
- No heartbeat/renewal, no auto-reclaim, no GitHub API: open PRs must be passed in via `--open-prs`. `RECLAIMABLE` depends on the claimer's committer clock (claim commit committer date, falling back to lease `acquiredAt`): a skewed claimer clock yields wrong ages, and future-dated claims are reported `UNKNOWN`. Open PRs are never discovered automatically: a task whose branch has an open PR is only protected if the caller passes it in via `--open-prs`.
- Read-only dry run (no `--claim`) reports START with `claimed:false`; it reserves nothing.
- Backlog edits (status changes) are still done by humans/PRs; the dispatcher never writes the backlog.
- Proof: `node docs/planning/dispatch.proof.mjs` (temp git repos only). The remote lease path was exercised only against local bare repos, not a live GitHub origin.
